# How the alignment and torsion tree work

Read this when you need to reason about *why* a run behaved as it did, when
warheads fail to map, or when you want the alignment without the docking.

## The five steps of prep

1. **Embed the PROTAC onto the E3 warhead.** MCS between PROTAC and E3 warhead;
   the matched atoms are pinned to the warhead's coordinates and the rest is
   generated by distance geometry.
2. **Re-embed onto the target warhead, E3 part rigid.** The target-matched atoms
   are pinned to the target warhead's coordinates while the E3-matched atoms are
   held as a rigid body via pairwise distance bounds, then transplanted exactly
   by Kabsch.
3. **Kabsch transform.** The rigid-body rotation+translation taking the E3
   warhead from where it started to where it ended up. This is what carries the
   whole E3 protein.
4. **Torsion tree.** Target warhead becomes the root; warhead-internal rotatable
   bonds are frozen; only linker bonds stay active.
5. **Merge and write DMS.** The E3 protein is transformed by (R, t) and merged
   into the ligand as a rigid extension.

The docking "ligand" is therefore PROTAC + entire E3 protein — 900 atoms for
MZ1+VHL — with only the linker torsions free.

## Why the warhead constraint is the premise, not a result

Both warheads are pinned to poses you supplied. Their agreement with a reference
is an input, not a prediction. What the search actually determines is the linker
conformation, and through it the position of the E3.

## Frame sensitivity

Distance-geometry embedding pins atoms to *absolute* coordinates, so it is not
equivariant under rigid motion of the inputs. Rigidly moving the whole E3 side
(warhead + protein together) changes the linker conformation that comes out:

| E3 inputs moved by | resulting E3 placement differs by |
|---|---|
| 5 Å translation | 0.00 Å |
| 50 Å translation | 4.73 Å |
| 115° rotation + 77 Å | 11.59 Å |

The target warhead stays bit-identical and the Kabsch fit is perfect in every
case — only the linker differs. Small offsets are harmless; large ones are not.
If your two binary complexes come from different PDB entries, translate them
near each other before prep.

This matters less than it sounds for the full pipeline, because docking
re-randomises all linker torsions anyway. It matters a lot if you treat the
alignment output as an answer.

## Why warhead matching fails

`rdFMCS.FindMCS` is called with `CompareAnyHeavyAtom` and `CompareOrderExact`,
plus `ringMatchesRingOnly` and `completeRingsOnly`. Consequences:

- A wrong **element** in your SDF still matches — silently.
- A wrong **bond order** does not, and shrinks the MCS.
- Partial rings are excluded, so a warhead differing from the PROTAC by a ring
  substitution can lose the whole ring.

Check the mapped atom count in the log against the warhead's heavy-atom count.
For MZ1 they are equal (32 of 32 for VHL, 27 of 27 for the BRD4 side); anything
much lower means the warhead and the PROTAC disagree chemically.

## Alignment without docking

Needs only rdkit, numpy and networkx — no engine, no msys, no compiled code.
`msys` is imported lazily inside the DMS builders, so it is not required here.

```python
import sys; sys.path.insert(0, "<repo>/examples/protac_docking")
import numpy as np
from rdkit import Chem
import protac_sampling as ps

protac = Chem.SDMolSupplier("degrader.sdf",      removeHs=False)[0]
ep     = Chem.SDMolSupplier("e3_warhead.sdf",    removeHs=False)[0]
tp     = Chem.SDMolSupplier("target_warhead.sdf", removeHs=False)[0]

ep_m, ep_r = ps.find_mcs_mapping(protac, ep)
p1 = ps.constrained_embed(protac, ps._build_coord_map(ep_m, ep, ep_r),
                          orig_conf=protac.GetConformer(), seed=42)
before = ps._get_coords(p1, ep_m)

tp_m, tp_r = ps.find_mcs_mapping(p1, tp)
p2 = ps.constrained_embed_with_rigid_group(
        p1, ps._build_coord_map(tp_m, tp, tp_r),
        rigid_atoms=list(ep_m), ref_conf=p1.GetConformer(), seed=42)

R, t = ps.kabsch_transform(before, ps._get_coords(p2, ep_m))

e3 = Chem.MolFromPDBFile("CRBN.pdb", removeHs=False)
e3_moved = (R @ e3.GetConformer().GetPositions().T).T + t
```

`p2` is the aligned PROTAC; `(R, t)` places the E3 protein.

Sanity checks worth printing: the Kabsch RMSD (should be ~0 — it measures
whether the E3 warhead moved rigidly) and `det(R)` (should be +1; a negative
determinant means a reflection crept in and the result is wrong).

## What the input conformer does and does not affect

The PROTAC's input conformation is used only as a ring-puckering reference. Two
completely different input conformers produce a byte-identical prep output,
because the warheads are pinned and the linker is regenerated from a fixed
distance-geometry seed. So there is no point generating a "good" starting
conformer — but equally, the prep output is not a sample from the linker's
conformational ensemble.
